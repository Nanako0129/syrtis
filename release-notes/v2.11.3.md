## Fixes

- **Cursor usage syncs for accounts on the new billing whose usage carries another user id.** [#559](https://github.com/Nanako0129/syrtis/pull/559) — thanks [@ohari5336](https://github.com/ohari5336), who reported the failure in [#520](https://github.com/Nanako0129/syrtis/issues/520) and ran the two checks that decided the fix

  On v2.11.2, a migrated Cursor account's sync could end with "Cursor returned usage of another account, so Syrtis saved nothing (billing_v2_principal_mismatch)." Syrtis required every usage item from Cursor's new billing to belong to the user id in the Cursor sign-in. The reporter's check showed that all 100 items of their last 7 days belonged to one user id of the same form but a different value.

  Syrtis now accepts, within one sync, items on the sign-in's own user id, as before, and items on one other user id that Cursor marks as a user. A second other user id, an account that is not a user (such as a team), or an item without an owner still ends the sync with that code, and nothing is saved. Anything v2.11.2 accepted is still accepted.

  This has not run against an account on the new billing; it was tested against a local stand-in server shaped like the reporter's results.

- **Gemini models appear under one name, and one row per model in a tab that spans several clients.** [#558](https://github.com/Nanako0129/syrtis/pull/558)

  The Models card and the Models view listed `gemini-4-argon-c` and `gemini-4-argon-trial` beside `gemini-4-argon`, and `gemini-3.5-flash-high` beside `gemini-3.5-flash`. They are now shown under the bare model name; the `gemini-3.5-flash` medium, low and extra-low tiers fold the same way. Only the displayed name changes: prices, the usage cache and exports keep the original label, and nothing is re-read.

  The Antigravity tab showed `gemini-3.8-flash` twice, once for the agy CLI and once for the extension. In a tab that covers more than one client, a model from one provider is now one row, and hovering over it lists each client's tokens and share. A row whose cost is flagged as implausible is never merged with others, so the flag stays on its own row. "Favorite model" in Stats is picked from the same rows.

  On the maintainer's Mac, a test build showed `gemini-3.8-flash` once on the Antigravity tab with both clients in its tooltip, no `-c`, `-trial` or `-high` rows, and `gemini-4-argon` as a single row on the Claude tab. Run over a copy of the same usage data outside the app, each client's tokens and message counts were the same before and after the fold.
