Before you update:
- Antigravity quota is no longer read while the Antigravity app is closed, unless you turn it on. Syrtis used to ask Google with Antigravity's saved Google sign-in, or run the agy CLI; Google's Antigravity terms say third-party access can lead to account suspension, so for the main card both are now off for everyone. With Antigravity closed the card says it isn't running. To bring the old behaviour back, turn on "Read quota while Antigravity is closed" in Settings -> Accounts -> Antigravity. Accounts added with Capture are still read with their saved Google sign-in. Thanks @iF2007.

Features:
- Syrtis can combine usage from your other Macs. On the new Settings -> Devices page, one Mac approves a scan scope, turns on sharing and creates an invitation (good for 10 minutes); the other pastes it under "Link another device", and both confirm the same short code. Only totals are sent (tokens, cost, message and turn counts, duration, by day, hour, client, model, provider and agent name), never conversation content or file paths. A device menu beside the year menu then adds the ticked devices into Overview, Stats, Daily, Monthly, Models, Hourly and Agents. Quota and usage inside quota windows still count this Mac only. Both Macs need 2.12.0 or newer; the Windows app gets Devices in a release of its own.
- Limits of combined usage: sessions that two devices sync are counted on both (a warning appears), "All years" covers the last 370 days for other devices, and a sharing Mac with no readable price table reports cost 0 for clients that don't record their own cost, with a note on the dashboard.
- Linux machines can be read over SSH: under "SSH machines" on the Devices page, type a host or ssh alias. Syrtis installs its usage agent there over your ssh (pinned sha256), keeps an ssh tunnel, pairs through it after you approve the scan scope on your Mac, and copies its price table so costs are calculated. It uses your ssh config and ssh-agent and never accepts an unknown host key. Linux x86_64 with glibc 2.35 or newer only. Remove from the app and machines without systemd were not run on a real machine. Thanks @miyago9267.
- The Droid tab shows Factory plan limits once you save a Factory API key under Settings -> Accounts -> Factory. The key stays in your login Keychain and is sent to api.factory.ai on each refresh. Not run with a real key here. Thanks @changshunxu520.
- Discord status can count the other devices ticked in the dashboard ("Include other devices selected in the dashboard" in Settings -> Discord, off by default), updated about every 5 minutes.
- Command-W closes the Settings window; Syrtis keeps running. Asked for by olilllioli287 on Discord.

Fixes:
- The main Claude card's quota window read 0 when another Claude account's folder linked to the same transcripts (projects symlinked to ~/.claude/projects). Totals were not affected.
- In an app left open for hours, two background report calls could wait on each other, after which the dashboard stopped refreshing.
- The live token rate check reads only the cache parts for files that changed instead of the whole message cache every 10 seconds, and opening the dashboard with other devices ticked computes the graph once. Reported numbers are unchanged.
- Models lists count distinct models, show the provider beside a model that has one row per provider, and pick "Favorite model" by the model's rows together.
- Sync Now gets through several Cursor profiles: the round's time limit grows with the number of profiles (15 minutes each, up to 45), and a page that times out or gets a server error is tried up to three times. Timings go to cursor-sync-debug.log in ~/Library/Application Support/com.nyanako.tokenbar, never your Cursor login. Thanks @ohari5336.
- When read from the running Antigravity app, the quota card shows the weekly and grouped limits. Thanks @savourylie.
- A partial Cursor sync names its cause (timeout, budget_exhausted or too_many_pages), and a failed write of the downloaded file can no longer make the next sync treat current usage as old history. Thanks @ohari5336.
- Paste, Copy, Cut and Select All shortcuts work in Settings text fields, and every Settings switch has a VoiceOver label.
