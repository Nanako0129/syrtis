## Before you update

- **Antigravity quota is no longer read while Antigravity is closed, unless you turn it on.** [#598](https://github.com/Nanako0129/syrtis/pull/598) — thanks [@iF2007](https://github.com/iF2007) for [#596](https://github.com/Nanako0129/syrtis/issues/596)

  Until now, when the Antigravity app wasn't running, Syrtis asked Google for the quota with Antigravity's saved Google sign-in, and failing that ran the `agy` CLI. Google's Antigravity terms say that using third-party software to access the service can lead to account suspension, so for the main card both are now off for everyone, existing installs included. With Antigravity closed the card reads "Antigravity isn't running. Open it to see quota, or allow reading while it's closed in Settings › Accounts › Antigravity." (in English in every language). While the app is running nothing changes: Syrtis reads the quota from it on this Mac.

  To get the old behaviour back, turn on "Read quota while Antigravity is closed" under Settings → Accounts → Antigravity and confirm. Accounts you added there with Capture are not affected by the switch: they are always read with their saved Google sign-in, which carries the same risk, and the section now says so. Syrtis does not detect an account Google has already blocked.

## Features

- **Syrtis can combine usage from your other Macs.** [#566](https://github.com/Nanako0129/syrtis/pull/566), [#567](https://github.com/Nanako0129/syrtis/pull/567), [#568](https://github.com/Nanako0129/syrtis/pull/568), [#569](https://github.com/Nanako0129/syrtis/pull/569)

  Settings has a new Devices page. On the Mac whose usage you want to read, approve the scan scope, turn on "Share this Mac's usage", pick a listen address and press "Create invitation". The address list starts at "This Mac only (127.0.0.1)", so choose one of the Mac's own addresses for another Mac to reach it. On the other Mac, paste the invitation under "Link another device". Link first shows the address it will connect to; a second press connects. Both Macs then show a short code, and the sharing Mac approves once the two match. An invitation expires after 10 minutes. Sharing is off until you set it up, and both Macs need 2.12.0 or newer.

  What is sent is totals: token counts, cost, message and turn counts and duration, grouped by day and hour and by client, model, provider and agent name, plus the device name if you set one. Conversation content, file paths and account fields are not sent. Access lasts until you revoke it under "Devices with access"; removing a linked device also deletes the usage this Mac kept from it.

  A device menu appears beside the year menu in the dashboard once a device is linked. Overview, Stats, Daily, Monthly, Models, Hourly and Agents add up the devices you tick, with a "Per device" card under Overview, Monthly and Daily. Quota, Agent limits and usage inside quota windows still count this Mac only, and say so. Other devices are asked every 5 minutes. When one doesn't answer, a line above the page says why (can't reach it, busy, stopped sharing) and how old the figures shown are.

  Limits worth knowing before you rely on the totals:

  - If two devices sync the same session files, those sessions are counted on both. A warning appears; nothing is deduplicated.
  - For other devices, "All years" covers the last 370 days.
  - Up to 16 other devices can be ticked at a time.
  - The first answer from a Mac with a very large history took about 80 s in one test, and the page shows "has no data to show" for that device until it arrives.
  - A sharing Mac with no readable price table reports cost 0 for clients that don't record their own cost, such as Claude. The dashboard then says that device's cost may be incomplete.

  Syrtis for Windows does not have Devices yet; it comes in a Windows release of its own.

- **Linux machines can be read over SSH.** [#593](https://github.com/Nanako0129/syrtis/pull/593) — thanks [@miyago9267](https://github.com/miyago9267)

  "SSH machines" on the Devices page is for a Linux box you can ssh into but that has no port open to your Mac. Type its host or ssh alias and press "Add and deploy". Syrtis uploads its usage agent to `~/.local/bin/syrtis-agent` over `/usr/bin/ssh`, checks the upload against a pinned sha256, starts it as a systemd user unit (or as a detached process where systemd is unavailable), keeps an ssh tunnel to it and pairs through the tunnel. Before anything is shared, your Mac shows what the agent will read on that machine and waits for "Approve and pair". Cancel undoes what the add did there, except that an agent build it replaced is not put back. The machine then appears in the device menu like a linked Mac. Syrtis also copies its price table to the machine, so usage that carries no cost of its own is priced there.

  It uses your `~/.ssh/config` and ssh-agent and never accepts an unknown host key: connect once in a terminal first. A `LocalForward` or `RemoteForward` in the alias opens together with Syrtis's tunnel and can make it fail, so use an alias without forwards. The machine must be Linux x86_64 with glibc 2.35 or newer; ARM and musl are not supported. If your home folder there, or one of the folders the agent installs into (`~/.local`, `~/.config` and below), is writable by group or others, Syrtis uploads nothing and shows the `chmod go-w` command to run.

  Removing a machine revokes this Mac's access there, and can also uninstall the agent and delete its data unless other devices still use it. Two things to know: adding a machine restarts an agent that is already running there, and quitting Syrtis in the middle of an add can leave the agent installed with nothing recorded for a retry. Add, pairing and the price copy were run on Linux hosts with systemd. Remove from the app and the start-up path for machines without systemd were not run on a real machine.

- **The Droid tab shows Factory plan limits.** [#571](https://github.com/Nanako0129/syrtis/pull/571) — thanks [@changshunxu520](https://github.com/changshunxu520)

  Paste a Factory API key under Settings → Accounts → Factory and the Droid tab's quota cards fill in: 5-hour, weekly and monthly windows for the Standard and Core tiers, whichever your plan has. The key is kept in your login Keychain and sent to api.factory.ai each time the quota refreshes; without a key nothing is requested. The cards were built from the response format in the contributor's report. We have no Factory key, so saving a key and the live cards were not run here.

- **Discord status can count the other devices you ticked.** [#584](https://github.com/Nanako0129/syrtis/pull/584), [#591](https://github.com/Nanako0129/syrtis/pull/591)

  "Include other devices selected in the dashboard" under Settings → Discord is off by default. When on, today's tokens, cost and most-used client come from this Mac plus those devices, updated about every 5 minutes. A device that can't be reached counts with its last figures, and after three failed updates in a row the status goes back to this Mac alone until one succeeds.

- **Command-W closes the Settings window.** [#595](https://github.com/Nanako0129/syrtis/pull/595) — asked for by olilllioli287 on Discord

  Syrtis keeps running in the menu bar. With the dashboard open, Command-W closes the dashboard.

## Fixes

- **The main Claude card's quota window read 0 when another Claude account's folder linked to the same transcripts.** [#561](https://github.com/Nanako0129/syrtis/pull/561)

  This happened when an extra account folder's `projects` was a symlink to `~/.claude/projects`, or the folder itself was a link to `~/.claude`. Each card now counts what its own folders reach. Totals were never affected, only usage inside the main card's windows.

- **In an app left open for hours, the dashboard could stop refreshing.** [#588](https://github.com/Nanako0129/syrtis/pull/588)

  Two background report calls could end up waiting on each other. After that no background report came back and the refresh indicator never settled. It was seen in a running app after about six hours; v2.11.3 has the same code.

- **The live token rate uses less CPU.** [#590](https://github.com/Nanako0129/syrtis/pull/590), [#589](https://github.com/Nanako0129/syrtis/pull/589)

  The 10-second rate check loaded the whole message cache each time; it now reads only the parts that belong to files that changed. Opening the dashboard with other devices ticked also computes the usage graph once instead of twice. Reported numbers are unchanged.

- **Models lists count and rank by model.** [#564](https://github.com/Nanako0129/syrtis/pull/564), [#565](https://github.com/Nanako0129/syrtis/pull/565)

  The "N models" header counts distinct models. A model used through two providers keeps one row per provider, with the provider shown beside the name, and "Favorite model" in Stats is the model whose rows cost most together.

- **Sync Now gets through several Cursor profiles.** [#597](https://github.com/Nanako0129/syrtis/pull/597) — thanks [@ohari5336](https://github.com/ohari5336), who wrote the fix after reporting it in [#520](https://github.com/Nanako0129/syrtis/issues/520)

  With several profiles, the whole round shared one time limit, and the later profiles ended in "Only part of your usage was downloaded". The limit now grows with the number of profiles: 15 minutes per profile up to 45 for Sync Now, 3 minutes per profile up to 20 in the background. It is still shared, so one slow profile can use most of it. A page that times out or gets a server error from Cursor is tried up to three times, and one page may take 90 seconds instead of 15.

  Syrtis also writes `cursor-sync-debug.log` in `~/Library/Application Support/com.nyanako.tokenbar` while Cursor sync is on: event names, counts and timings, never your Cursor login. Turning Cursor sync off deletes it. This was tested against a local stand-in server; a real sync with several profiles was not run here.

- **Antigravity's local quota shows the weekly and grouped limits.** [#556](https://github.com/Nanako0129/syrtis/pull/556) — thanks [@savourylie](https://github.com/savourylie)

  When Syrtis reads quota from the running Antigravity app, it now asks for the app's grouped summary first, so the card carries the weekly and model-family rows; the per-model quotas are used only when the summary has none. Pace history for those rows starts over once. The maintainer's Mac doesn't take this route, so the card was not seen there.

- **A partial Cursor sync says why.** [#562](https://github.com/Nanako0129/syrtis/pull/562), [#563](https://github.com/Nanako0129/syrtis/pull/563) — thanks [@ohari5336](https://github.com/ohari5336) for the reports in [#520](https://github.com/Nanako0129/syrtis/issues/520)

  "Only part of your usage was downloaded (timeout). Syrtis will try again." now names `timeout`, `budget_exhausted` or `too_many_pages`. Separately, a failed write of the downloaded file can no longer make the next sync treat current usage as old history.

- **Paste, Copy, Cut and Select All shortcuts work in Settings text fields.** [#577](https://github.com/Nanako0129/syrtis/pull/577)

- **Every switch in Settings has a VoiceOver label.** [#572](https://github.com/Nanako0129/syrtis/pull/572)
