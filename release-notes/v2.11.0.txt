Before you update:
- The first launch after updating reads all your Claude logs again, once. On the maintainer's data (5,323 files, 11 GB) the first refresh took about a minute of high CPU: 34 s of CPU at a machine load of about 6, and 58 s at about 14. It can take longer with more history, and the menu bar title and the popover's background reports can wait behind it. Droid, Qwen, Roo Code, Kilo Code and Cline are also read again once.
- Going back to v2.10.0 or earlier loses Claude turns that only the cache still holds, because Claude Code has since compacted them out of its own logs, unless you restore a backup. Before you install the update, quit Syrtis and any tokscale process and copy cache/source-message-cache-v2/claude/ from ~/.config/tokscale (or the folder TOKSCALE_CONFIG_DIR names). To go back: quit everything that runs v2.11.0, put that folder back, then start the older version. Start no other version before the restore is finished. An older build that scans the same folder after v2.11.0 has written to it does the same damage.

Features:
- Settings has an Accounts page. Claude, Antigravity and Cursor moved there from General, next to new sections for Pi and DeepSeek Harness. Turning on Cursor sync now opens a confirmation (Cancel or Continue) and enables nothing until Continue.
- Pi can read additional folders ("Add folder…" in Settings -> Accounts -> Pi), such as usage-only exports from headless runs that write nothing under ~/.pi/agent/sessions. Thanks @savourylie.
- DeepSeek Harness can read the sessions folder of another DSH home; its usage joins your DSH total. Thanks @darkskygit.
- Several Cursor profiles sync into one Cursor total: add a folder you start Cursor with using --user-data-dir under Settings -> Accounts -> Cursor, up to 32 profiles. An account signed in to several profiles is downloaded once. Thanks @ohari5336.
- Antigravity conversation databases in ~/.gemini/antigravity/conversations, where the Antigravity desktop app writes, are read and shown as "Antigravity Extension" inside the Antigravity tab. Thanks @rsimenok.
- A custom OpenCode database location is scanned: OPENCODE_DB, or scanner.opencodeDbPaths in tokscale's settings.json. OPENCODE_DB is read when Syrtis starts. Thanks @sunjeel25, whose Windows report this was ported from.

Fixes:
- Claude input tokens were overcounted for some requests. On the maintainer's data Claude input went from 47.96M to 19.63M (-59.1%) and cost moved -0.23%.
- A transcript symlinked into an extra Claude account's folder was counted for the main account too; it now counts for the extra account only.
- Opening the popover after idle is faster. On copies of the maintainer's data the first open after two idle minutes took 3.7 s instead of 14.5 s, and mean CPU went from 13.4% to 0.8% (the second run had a lighter machine load, so indicative).
- Background refreshes use one core instead of two, and price lookups cost less CPU. In a 10-minute run on the maintainer's data, total CPU went from 71.0 s to 58.9 s and the 10-second windows above 100% from 4 to 1, the one left being the first launch above. Measured in the engine on a heavily loaded machine, one graph computation took a median of 7.68 s of CPU instead of 10.42 s, with identical reports.
- Codex usage dropped out of reports once sessions 7 days or older were compressed to .jsonl.zst; Syrtis now decodes them. The reporter measured about 5.06B of 12.59B Codex tokens missing over 15 days on one Mac. Thanks @patrick-fu.
- Roo Code and Kilo Code tasks in VS Code are now scanned. A positive cost reported by Roo Code, Kilo Code or Cline is kept instead of re-estimated, so cost totals shift. For Roo Code and Kilo Code rows dated 2025-11-02 UTC or later, input no longer includes the cache buckets twice, so input totals drop. Some rows change provider; check saved assignments under Settings -> Usage attribution.
- Hermes reasoning is no longer counted twice, Qwen's cached prompt tokens leave its input count, and totals and estimated cost drop for both. Droid replies are counted on the date each was written. Kilo CLI skips migration stub rows.
- Models priced from a reseller's listing are now priced from the vendor's own row. On the maintainer's data, with one frozen price snapshot, 4 of 76 model rows changed and the total went from $33,797.96 to $33,276.84 (-$521.12, -1.54%): Anthropic -$452.16, OpenAI -$68.97, Google and xAI $0. codex-auto-review is now estimated as gpt-5.1-codex-mini instead of gpt-5.3-codex ($124.14 to $61.22 over 2,140 messages).
- Antigravity Gemini 3.8 Flash route labels now show as one model, gemini-3.8-flash, and nameless Antigravity CLI rows get a model. A usage attribution saved for a renamed label or changed provider no longer matches; assign it again. Thanks @qqeet for tokscale-core#34.
- OpenRouter's published cache rates are kept instead of dropped. Thanks @kizaki-R.
- With Reduce Transparency on (Accessibility > Display), Settings cards no longer turn dark grey. Thanks @yellowsoar.
- The Antigravity switch under Settings -> Dashboard -> Client tabs (top bar) can bring a hidden tab back again. Thanks @savourylie.
- A refused folder add now opens an alert with a one-sentence reason. Claude config dirs also refuse ~/.claude itself and every folder already read for the main Claude account (the list holds at most 8), which could previously zero the main account's usage in its quota windows.
- Antigravity: turning on automatic capture asks first ("Turn on automatic capture?"), a failed automatic capture shows a sentence instead of nothing, and Remove no longer lets an in-flight refresh write the account back.
- The Accounts page copy says where the Claude sign-in is read, that it isn't logged and which host gets which token, and a Cursor cleanup failure or refused sync now says so.

Known issue:
- Capturing an Antigravity CLI (agy) login fails with agy 1.4.12, the version checked: agy no longer stores the account identity Syrtis reads. Capture current agy login and automatic capture stop with "agy's saved login doesn't say which Google account it is. Sign agy in again, then try again." v2.10.0 reads the same field, so this is not new. A fix is planned for the next release.
