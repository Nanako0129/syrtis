## Fixes

- **Syrtis kept more than half of a CPU core busy while the popover was open.** [#484](https://github.com/Nanako0129/syrtis/pull/484) — thanks [@miyago9267](https://github.com/miyago9267)

  While an agent was writing, the green activity light next to the tok/min rate redrew the whole popover up to about 120 times a second. The light now blinks without redrawing the popover. The popover's content also ran, unseen, from launch until the popover was first closed; it now runs only while the popover is open.

  Measured with the built-in demo data on the maintainer's Mac: with the popover open, the main thread alone used 57.5% of one core before, and the whole app now uses 2.1%. In the first minute after launch, with the popover never opened, the app used 59% of one core before and 0.17% now.

  Not changed in this release: Syrtis rebuilds its usage totals every Data refresh interval, or every 5 minutes while an agent is active if that is sooner, and each rebuild shows as a short spike in CPU use.

- **An unused Antigravity window read "Pace unavailable · invalid quota data", or started a new window on every update.** [#478](https://github.com/Nanako0129/syrtis/pull/478)

  Since v2.4.0, Antigravity's weekly and 5-hour windows take their length from what agy and Google report. Until a window is used, Google moves its reset forward on every reading, so the window never has a fixed start. With this Mac's clock behind Google's the card showed that message; otherwise each update started a new window in its history. An unused window now reads "Learning reset duration" until you use it.

- **An Antigravity account on a paid Google AI plan was labeled Free.** [#477](https://github.com/Nanako0129/syrtis/pull/477)

  The card now shows the name of the paid plan Google reports for the account. When agy's main card is merged with its captured account, it also shows that account's plan next to its email.

- **With automatic capture on, an account agy signed in to during a capture could be shown with the previous account's email.** [#474](https://github.com/Nanako0129/syrtis/pull/474)

  Syrtis now checks that agy's sign-in did not change while it was capturing. If it did, Syrtis does not link the previous account to the new sign-in, and captures the new account on its next check.

- **An extra Claude account's window card counted usage of another account kept inside its folder.** [#473](https://github.com/Nanako0129/syrtis/pull/473)

  For example, with both a folder and its `.claude` subfolder configured, the folder's window counted the subfolder account's usage as well as its own. Each window now counts only its own account's Claude usage.

- **The Grok tab showed no window card when only Grok Bot was set up.** [#471](https://github.com/Nanako0129/syrtis/pull/471)

  The Grok Build & Bot tab now shows Grok Bot's window card and window history in that case.

- **Switching off OpenCode under Settings → Dashboard → Agent limits also hid the other quota cards on the OpenCode tab.** [#480](https://github.com/Nanako0129/syrtis/pull/480)

  The cards for the subscriptions OpenCode is signed in with now stay visible. The OpenCode tab's limits card is hidden only when all of them are switched off as well.

- **OpenCode Go's "Rolling" window was not translated in Chinese.** [#471](https://github.com/Nanako0129/syrtis/pull/471)
