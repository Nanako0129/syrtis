## Maintenance posture

維護期的排序是 user-reported correctness 優先，其次是可驗證的資料遺失、stale cache、跨語言契約與 release chain 問題；新 client breadth 或大型 UI 重構沒有自動優先權。公開 issue [#45](https://github.com/Nanako0129/syrtis/issues/45) 是完整 upstream inventory 與決策面，不是「每一列都必須清掉」的 backlog。

> **接手原則：** 先確認問題是否影響實際使用者的數字或更新路徑，再決定要修、報上游、defer，或明確 parked。不要把 inventory 的數量當成工作量承諾。

The preceding advance brought a **determinism fix for pricing fallback ordering** (engine PR #23 by @huyanxius, Syrtis issue #300). Equal-length fallback candidates were taken in `HashMap` iteration order, which changes when the pricing snapshot is rebuilt, so **the same usage could pick a different rate after a pricing reload and a historical cost would move with no new usage behind it**. Ties now break lexicographically after the length-descending sort. The reporter reproduced it 200 times in isolation on a fixed synthetic catalog and got two answers ($10,000 in 117 runs, $8,000 in 83); after the fix that path returns one of them and stays there. An affected model settles **once** on a determinate value and stops moving — this is not a repricing, it is the end of a coin flip. Nothing in the parser or the cache schema changed there: `CACHE_FORMAT_VERSION` stayed 4 and every `parser_version` was unchanged, so that advance triggered no rescan and no migration — unlike the Codex turn fix directly above it, which is the one advance in this list that does. That advance was pin-only too: `crates/tb_core_ffi` and `ctb.h` were unchanged.

The preceding advance brought the **1-hour cache-write pricing fix** (engine PR #25, Syrtis issue #287). Anthropic bills a prompt-cache write at 1.25x base input with the 5-minute TTL and 2x with the 1-hour one, but the parser read only `cache_creation_input_tokens` — their sum — and priced all of it at the cheaper rate. It now reads the nested `cache_creation.ephemeral_1h_input_tokens`, and pricing **subtracts** the 1h portion from the cache-write bucket before repricing it at `2 x input_cost_per_token`; `cache_write` still means the whole write and `cache_write_1h` is a subset of it, so `total()` and every total sum are untouched. `parser_version(Claude)` moves 3 to 4, without which the fix reaches nobody who already has a cache — `get` treats a version-matching entry as a hit, so a transcript whose fingerprint has not changed is never re-parsed. The bump is non-lossy because the preceding advance's migration keeps retained-only turns reachable.

**Users will see historical costs rise.** Measured over the frozen 1,144-transcript corpus, the 1-hour TTL accounts for 79.6% of cache-write tokens (539,639,286 of 678,193,247) and cost moves $14,658.23 to $15,710.35, a 7.18% rise, with all four token lanes byte-identical — this changes what tokens cost, never how many there are. Release notes must say so, or the rise reads as the app becoming more expensive. The measurement is deliberately a warm-cache one (run the previous build to populate a cache at `parser_version` 3, then run this build against the same config dir), because that is what an upgrade does; the cold run agrees to the cent, and reverting only the bump returns $14,658.23 — a delta of exactly zero, which a cold-cache-only acceptance would have hidden. That advance was also pin-only: `crates/tb_core_ffi` was unchanged, the one-line fill having landed with the advance before it.

The preceding advance brought the format-crossing migration (engine PR #24), which closed tokscale-core issue #22: `CACHE_FORMAT_VERSION` moves 3 to 4, and for the first time a format bump migrates rather than discards. `mod format3` holds the old bincode layout, so a namespace that retains history — Claude, where the cache is the only copy of turns an in-place compact already removed — has its shards decoded and carried across, while every other namespace still goes cold exactly as before and re-scans once. **No reported number changes.** The bump exists because the same PR adds `TokenBreakdown::cache_write_1h`, which alters the positional bincode layout; the field carries the layout only and is neither populated nor priced yet, so #287's TTL pricing can land next without a second, lossy bump. Measured over the same frozen 1,144-transcript corpus, with a simulated compact removing 300 assistant turns that carried usage (404 to 104): format 4 reading the format 3 cache returned input 868,733,624 / output 44,261,347 / cache_read 16,769,237,791 / cache_write 289,163,123, identical in all four lanes to the format 3 baseline, while a cold-cache control on the same compacted corpus came back lower by input 376 / output 121,248 / cache_read 49,249,515 / cache_write 573,038 — the control is what makes the result falsifiable. That advance was not pin-only: `crates/tb_core_ffi` needed one line, because `local_cost_estimate` builds a `TokenBreakdown` literal exhaustively and must now name the new field. It was not a `ctb.h` signature change, so the Windows port is not a notified consumer under that rule, but the same one-line fill will be required there when its pin advances — and that fill is now `cache_write_1h: entry.cache_write`, not `0` (Syrtis PR #309). The estimate is the denominator of the implausible-cost ratio, so only an upper bound on it is safe: filling `0` prices the write at the 5m rate, which a resale entry lacking `cache_creation_input_token_cost` drops entirely while the engine still bills it, inventing warnings on locally priced rows. See [`vendor-tokscale.md`](vendor-tokscale.md) for the measured case. The advance before that brought the Claude shard migration (engine PR #21): a `parser_version` 2-to-3 bump no longer discards retained-only turns, so **#288's tool_result correction reaches existing cache entries** rather than only transcripts that change next; measured over the same corpus, 253 shards took the migration path and all four lanes matched the baseline byte-for-byte against a lower cold-cache control. The one before that was adopted for the Claude `tool_result` correction (engine PR #19, Syrtis issue #288, porting upstream `275bc798`): the parser no longer char-estimates a `tool_result` whose text the next assistant turn already reports, so **reported Claude input tokens fall, by an amount that varies with the corpus**.
